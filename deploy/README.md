# Публикация результатов на сайты QP через GitHub (канон с 30.10.2026)

Этот репозиторий — очередь публикации. Робот на CX43 проверяет изменения каждые 2 минуты
и сам раскладывает папки по сайтам. Прямой scp больше не нужен.

## Как опубликовать

1. Собери результат в папку `deploy/<сайт>/<префикс><номер>/`: в корне `index.html`,
   статика рядом, имена файлов латиницей.
2. Префиксы: `z`=ZCode, `k`=Kimi, `c`=Claude, `x`=Codex. Номер сквозной по своему
   префиксу (k1, k2, k3…). Чужие префиксы не занимать.
3. В `<head>` каждой страницы обязательно:
   `<meta name="robots" content="noindex, nofollow">`
4. Закоммить и запушь в `main` ветку этого репозитория (mppressgurwitz-pro/claude).
5. Через 2–3 минуты проверь публикацию по уникальной строке из своего `index.html`
   (раздел «Проверка тела»). Код 200 нужен вместе с этой строкой:
   `curl -s -o /dev/null -w '%{http_code}' https://<домен>/<префикс><номер>/`.
   Лог робота: `/var/log/qp-deploy.log` на CX43 (root@2.28.43.63).
6. Отправь ссылку `https://<домен>/<префикс><номер>/` в группу сайта в Telegram.

## Сайты и домены

| Папка в репо | Публикуется на |
|---|---|
| deploy/events/<папка>/ | https://events.pressgurwitz.art/<папка>/ |
| deploy/savaceherbs.ru/<папка>/ | https://savaceherbs.ru/<папка>/ |

## Пример

`deploy/events/k1/index.html` — страница канала `k`, номер 1, сайт events (коммит 30.10.2026).

- Папка `k1` совпадает с шаблоном `<префикс><номер>`.
- В корне папки файл `index.html`, имя латиницей.
- В `<head>` стоит `<meta name="robots" content="noindex, nofollow">`.
- Уникальная строка для проверки: `Канал публикации работает`.
- Адрес по таблице выше: `https://events.pressgurwitz.art/k1/`.

Файл прямо в `deploy/` или папка без префикса и номера под правило синка не подходят.

## Проверка тела

```bash
curl -fsS "https://events.pressgurwitz.art/k1/" | grep -F "Канал публикации работает"
```

Ожидаемый вывод — строка из `deploy/events/k1/index.html`. Пустой вывод значит, что по URL
отдаётся другой документ.

На 2026-11-02 `curl` по `https://events.pressgurwitz.art/k1/` вернул 200 и документ
без строки `Канал публикации работает` и без заголовка
`Kimi k1 — тест канала публикации`. Путь
`https://events.pressgurwitz.art/does-not-exist-zz/` в тот же момент вернул 404.
Для выкладки нужны оба факта: код 200 и строка из закоммиченного `index.html`.

Тогда же `https://events.pressgurwitz.art/z1/` и `https://savaceherbs.ru/k1/`
отвечали 200, хотя папок `deploy/events/z1/` и `deploy/savaceherbs.ru/k1/` в git нет.
Перед новым номером открой URL: занятый номер может быть на сайте и отсутствовать
в этом репозитории.

HTML корня сайта (каталог «варианты дизайна») в этом репозитории не хранится. Пустая таблица на корне не заменяет проверку вложенного URL.

Если строка не находится, смотри `/var/log/qp-deploy.log` на CX43. Caddyfile, docker-compose, DNS и корень сайта этим репозиторием не меняются.

## Ограничения

Робот синкает только содержимое `deploy/` и только во вложенные папки вида <префикс><номер>.
Caddyfile, docker-compose, корень сайтов, DNS — не трогать никому. Правки за пределами
своей подпапки — стоп, вопрос штабу.

Техническая заметка: удаление файлов из репозитория при синке применяется (`--delete`)
только внутри папки <префикс><номер>/.
